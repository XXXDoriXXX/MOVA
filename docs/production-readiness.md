# Mova: перевірка готовності до продакшену

Дата: 2026-10-07. Ціль користувача: запуск на власному сервері та мінімум ручних кроків.

## Поточний висновок

Проєкт має основу для розгортання, але поточні файли не забезпечують надійного
продакшен-запуску. Цей документ — результат початкової перевірки, а не підтвердження
готовності. Код застосунків, налаштування сервера та чинні дані не змінювались.

Перевірено два репозиторії: `MOVA` (серверна частина та адмін-панель) і
`Mova-mobile` (Expo-застосунок). Обидва були без локальних змін на початку.
Каталогу `.codegraph` у них немає.

## Сервер: факти, перевірені через SSH

- `dev-server`, архітектура x86_64, 12 CPU.
- Пам'ять: 11958 MiB загалом, 6904 MiB доступно на момент перевірки.
- Диск: 492 GB загалом, 176 GB вільно.
- Docker 29.6.1, Compose v5.3.1.
- На момент перевірки працюють 18 контейнерів інших проєктів; Mova серед них немає.
- Адреса в локальній мережі: `192.168.1.70`.
- Порт 3010 уже зайнятий іншим проєктом; старий blue-green сценарій Mova його використовує.
- SSH доступний через Cloudflare Access. Старий сценарій VPS потребує root,
  встановлює nginx/certbot і скидає правила ufw: для цього сервера він непридатний.

Ці числа не доводять достатню потужність для конкретної кількості дзвінків.
Потрібна окрема перевірка під навантаженням і ліміти ресурсів.

## Перешкоди запуску

| Пріоритет | Знайдено | Що потрібно |
|---|---|---|
| Обов'язково | `docker-compose.yml` задає пароль Postgres `postgres`, базу `mova_dev` і примусово підставляє цю адресу в сервіси | Окремі продакшен-налаштування з обов'язковими секретами, узгодженими з підключенням застосунків |
| Обов'язково | Postgres, Redis та RedisInsight публікуються на всіх мережевих адресах | Залишити базу й Redis лише у внутрішній мережі контейнерів |
| Обов'язково | Продакшен-оновлення бази використовує образ API, але викликає `nx build`; Dockerfile runner не містить dev-залежностей і копіює лише збірку API | Окремий образ із готовими файлами міграцій і CLI TypeORM; без компіляції при запуску |
| Обов'язково | `.github/workflows/deploy.yml` працює лише вручну; ручний запуск пропускає перевірку CI | Перевірки перед кожним випуском; спочатку один перевірений ручний спосіб розгортання |
| Обов'язково | Перевірка випуску й інструкції використовують `/v1/health/live`, а код виключає health із префікса `v1` | Правильні `/health/live` та `/health/ready`, маршрути через зовнішню адресу |
| Обов'язково | `.last-good-deploy` записується до зовнішньої перевірки працездатності | Фіксувати успішний випуск лише після перевірок; попередній образ зберігати для повернення |
| Обов'язково | Адмін-панель є лише у dev override; продакшен-проксі її не обслуговує | Збирати статичну адмін-панель і віддавати її з тієї ж адреси, що й API |
| Обов'язково | `PAYMENT_PROVIDER` типово `mock`, WayForPay має типові тестові реквізити | Явно визначити режим запуску; комерційний продакшен не повинен непомітно працювати з тестовими платежами |
| Обов'язково | Без Resend листи підтвердження лише пишуться в лог разом із посиланням | Перевірити справжню доставку листів і прибрати токени підтвердження з продакшен-логів |
| Обов'язково | `restore-drill.sh` звертається до таблиці `user`, а entity задає `users`; помилка pg_restore ігнорується | Відновлення в окремій тестовій базі з правильною схемою та зупинкою при помилці |
| Обов'язково | Бекап читає DATABASE_URL з `.env`, але Compose її перевизначає | Бекап саме фактичної бази Mova, бажано через контейнер Postgres; перевірити відновлення |
| Обов'язково | `app.config.ts` мобільного застосунку дозволяє production-збірку з localhost | Перед збіркою вимагати справжні HTTPS/WSS адреси та перевіряти Firebase-файл |
| Після базового запуску | Майже всі допоміжні образи мають `latest`, повний моніторинг стартує завжди | Зафіксувати версії; розширений моніторинг увімкнути окремо |
| Після базового запуску | Мобільний код завантажує `@sentry/react-native`, але його немає в package.json | Перевірити production-збірку та налаштувати реальний збір помилок |

## Запропонований спосіб розміщення — ще не погоджено

Рекомендація: окремий Docker Compose проєкт у `~/mova`, PostgreSQL + Redis +
API + realtime + agent + вебпроксі зі статичною адмін-панеллю. LiveKit залишити
зовнішнім сервісом; не переносити голосовий транспорт у Cloudflare Tunnel.

Вебпроксі використовує окремий вільний порт (попередній кандидат 8794), доступний
чинному тунелю. Домен і маршрут тунелю ще потрібно визначити. У браузері API,
Socket.IO та адмін-панель використовують одну адресу. База та Redis не мають
опублікованих портів. Інші проєкти сервера не змінюються.

Спочатку локально перевірити збірки та запуск. Потім одна команда розгортання
передає лише файли проєкту, зберігає серверні секрети й дані, створює бекап перед
оновленням, запускає міграції та перевіряє готовність усіх сервісів. Окремі
короткі команди: стан, логи, бекап, повернення попереднього образу. Повернення
образу не означає автоматичного повернення схеми бази.

Альтернативи: збірка образів у GitHub із завантаженням на сервер зменшує
навантаження при випуску, але потребує налаштування доступів; окремий новий VPS
із nginx/certbot відділяє Mova від інших проєктів, але додає оплату й підтримку.

## Умови завершення

1. Чиста установка за короткою інструкцією; одна команда запуску після внесення секретів.
2. Успішні перевірки коду та збірки серверних образів, міграцій і адмін-панелі.
3. Міграції проходять на порожній базі та повторно без повторного застосування.
4. API readiness, Socket.IO й agent перевірені; підключення адмін-панелі працює.
5. Перезапуск зберігає дані; бекап відновлюється в окремому середовищі.
6. Мобільна release-збірка використовує потрібний сервер; перевірені вхід і дзвінок.
7. Є зрозумілий спосіб оновлення та повернення попереднього образу.
8. Для комерційного запуску перевірені справжні платежі, листи та потрібні push-сповіщення.

## Що ще не перевірено

Тести, нові збірки образів, реальні дзвінки, платежі, доставка листів і стан
Heroku ще не перевірені. Наявні локальні образи не є доказом збірки поточного
коміту. Compose config синтаксично проходить, але без `GHCR_OWNER` утворює
некоректні імена образів, а без `MOVA_DOMAIN` — некоректну зовнішню адресу Grafana.

Потрібно уточнити домен, долю чинних даних Heroku та режим платежів.
При перенесенні зашифрованих налаштувань зберегти чинний SETTINGS_ENCRYPTION_KEY.

Джерела щодо способу розміщення:
[Docker Compose у продакшені](https://docs.docker.com/compose/how-tos/production/),
[протоколи Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/routing-to-tunnel/protocols/).
