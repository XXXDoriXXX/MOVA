# Encrypted production secrets

This directory holds **sops-encrypted** files committed safely to
git. The plaintext `.env` for production NEVER lives here in clear
form — it gets decrypted at deploy time only.

## File naming convention

| Pattern        | What it is                                       |
|----------------|--------------------------------------------------|
| `*.enc`        | sops-encrypted env file                          |
| `*.enc.json`   | sops-encrypted JSON (configs, service-acct keys) |
| `*.enc.yaml`   | sops-encrypted YAML                              |

The `.sops.yaml` at repo root tells sops which age recipients can
decrypt these files (`encrypted_regex: ^(.*)$` = encrypt every value).

## First-time setup (operator)

```bash
# 1. Install sops + age.
brew install sops age            # macOS
# or: snap install sops; snap install age (Linux)
# or: scoop install sops age (Windows)

# 2. Generate your age keypair.
mkdir -p ~/.config/sops/age
age-keygen -o ~/.config/sops/age/keys.txt
# Note the line printed to stderr: "Public key: age1xyz..."
# That public key goes into .sops.yaml below `age:` so the team
# can encrypt for you.

# 3. Update .sops.yaml at repo root — replace the placeholder
#    age1xxxxxx... with your real public key, comma-separated if
#    multiple operators.

# 4. Re-encrypt existing files so your key can decrypt them.
#    (Only when adding a new recipient — first install does this
#    via step 5 below directly.)
#    sops updatekeys secrets/prod.env.enc

# 5. Create the encrypted prod env (one-shot):
sops --encrypt --input-type dotenv --output-type dotenv \
  /path/to/your/raw-prod.env > secrets/prod.env.enc

# 6. Verify decryption round-trips:
sops --decrypt secrets/prod.env.enc > /tmp/check.env
diff /path/to/your/raw-prod.env /tmp/check.env
shred -u /tmp/check.env /path/to/your/raw-prod.env
```

## Editing an existing encrypted file

```bash
# Drops you into $EDITOR with the decrypted content, re-encrypts
# on save. Never writes plaintext to disk.
sops secrets/prod.env.enc
```

## Deploy-time decryption

CI (GitHub Actions) decrypts at deploy time. Required secret:

| Secret name      | Value                                                 |
|------------------|-------------------------------------------------------|
| `SOPS_AGE_KEY`   | Contents of the deploy bot's `~/.config/sops/age/keys.txt` (one or more `AGE-SECRET-KEY-1...` lines) |

The deploy workflow:

```yaml
- name: Decrypt prod env
  env:
    SOPS_AGE_KEY: ${{ secrets.SOPS_AGE_KEY }}
  run: |
    sops --decrypt secrets/prod.env.enc > .env.prod
    # scp it to the VPS
    scp .env.prod $SSH_USER@$SSH_HOST:/opt/mova/.env
    shred -u .env.prod
```

See `.github/workflows/deploy.yml` for the full integration (gated
on the `SOPS_AGE_KEY` secret being set; without it, the encrypted
flow is skipped and the operator must place /opt/mova/.env by
hand).

## What goes into prod.env.enc

Everything from `.env` template generated by `infra/vps/bootstrap.sh`:
DATABASE_URL, JWT_SECRET, ADMIN_PASSWORD_HASH, all provider keys,
SETTINGS_ENCRYPTION_KEY, etc. The shape is documented in
`libs/shared-config/src/lib/env.validation.ts`.

## What does NOT go here

- API keys controlled by the admin UI (provider keys editable via
  `/v1/admin/settings`) — they're in Postgres `app_setting` table,
  encrypted with SETTINGS_ENCRYPTION_KEY (which itself lives here).
- Per-developer dev `.env` — those stay in repo root and `.gitignore`
  keeps them out of git.
- GitHub Actions secrets (SSH_PRIVATE_KEY, GHCR_PAT) — those live
  in GitHub's secret store, not here.

## Rotation

To rotate ALL prod secrets:

```bash
sops secrets/prod.env.enc       # edit, save
git commit -am 'rotate: prod secrets YYYY-MM-DD'
git push                         # CI re-decrypts + redeploys
```

To rotate ONLY a recipient's age key (e.g. operator left):

```bash
# 1. Remove their public key line from .sops.yaml.
# 2. sops updatekeys secrets/prod.env.enc
#    (re-encrypts the existing file with the remaining recipients;
#    the leaver's old age key can no longer decrypt newly-committed
#    versions, but obviously they already saw the plaintext while
#    employed — rotate the actual prod credentials in step 1 above.)
```
